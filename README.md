# Интернет-магазин «Web-Larёk»
«Web-Larёk» — учебный проект интернет-магазина с товарами для веб-разработчиков. В этой части проекта реализованы архитектура слоя данных, модели каталога, корзины и покупателя, а также получение каталога и отправка заказа через API.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model — слой данных, отвечает за хранение и изменение данных.  

View — слой представления, отвечает за отображение данных на странице.  

Presenter — презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

## Слой View

Слой представления состоит из отдельных компонентов, каждый из которых отвечает за один блок DOM и не хранит бизнес-логику. 
В проекте используются базовые классы `Component`, а также view-компоненты:

- `GalleryView` — отвечает за каталог товаров на главной странице;
- `CardCatalog` — карточка товара в каталоге;
- `CardPreview` — карточка товара в модальном окне подробного просмотра;
- `CardBasket` — товар в корзине;
- `BasketView` — блок корзины;
- `ModalView` — модальное окно;
- `OrderForm` и `ContactsForm` — форма оформления заказа и форма контактов;
- `FormBase` — общий базовый класс для форм, содержащий обработку ошибок и состояния кнопки отправки.

Каждый view-компонент хранит только ссылки на DOM-элементы и подписывается на событие. Логика принятия решений находится в презентере и в моделях, компоненты уведомляют о событиях пользователя

События моделей:
- `products:changed` — каталог товаров обновлён;
- `products:selected` — выбран товар для просмотра;
- `basket:changed` — изменилось содержимое корзины;
- `buyer:changed` — изменились данные покупателя.

События представлений:
- `select` — пользователь выбрал карточку товара в каталоге;
- `toggle` — пользователь нажал кнопку «Купить»/«Удалить из корзины» в карточке товара;
- `delete` — пользователь удалил товар из корзины;
- `checkout` — пользователь открыл оформление заказа;
- `submit` — пользователь отправил форму заказа или контактных данных.

Во всех подобных случаях презентер подписывается на события и обновляет состояние моделей и представлений без хранения логики в самих view-классах.

## Презентер

Презентер реализован в [src/main.ts](src/main.ts). Он является единственной точкой, где связываются модели, view-компоненты и API. В проекте выбран подход с одним презентером для одной страницы, без вынесения отдельного класса, что соответствует требованиям проекта и сохраняет простую архитектуру.

Презентер выполняет следующие задачи:
- загружает каталог товаров через `LarekApi`;
- сохраняет товары в модели `Products`;
- реагирует на выбор товара и открывает модальное окно с подробной карточкой;
- добавляет и удаляет товары в корзине;
- перерисовывает интерфейс корзины и обновляет счётчик товаров;
- открывает форму оформления заказа и форму контактов;
- валидирует данные покупателя, отправляет запрос на сервер и очищает корзину после успешной оплаты.

Использование данного подхода соответствует паттерну MVP: модель хранит данные, view отвечает за отображение и события, а презентер координирует взаимодействие между слоями.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Типы данных

`IProduct` описывает товар: идентификатор, описание, изображение, название, категорию и цену. Цена может быть `number` или `null`, если товар недоступен.

`TPayment` — доступный способ оплаты: `'card'` или `'cash'`.

`IBuyer` описывает данные покупателя: способ оплаты, email, телефон и адрес доставки.

`IOrder` расширяет `IBuyer` и добавляет массив идентификаторов товаров `items`, отправляемый при оформлении заказа.

`IProductsResult` описывает ответ GET-запроса каталога: общее количество товаров `total` и массив `items`.

`IOrderResult` описывает ответ POST-запроса заказа: идентификатор заказа `id` и итоговую стоимость `total`.

`IApi` задаёт контракт базового API-клиента с методами `get` и `post`.

## Модели данных

### Класс Products

Хранит каталог товаров и товар, выбранный для подробного отображения. Класс не зависит от DOM, API и других моделей.

Поля:

- `items: IProduct[]` — массив всех товаров каталога;
- `selectedProduct: IProduct | null` — выбранный товар.

Методы:

- `setItems(items: IProduct[]): void` — сохраняет каталог;
- `getItems(): IProduct[]` — возвращает каталог;
- `getItem(id: string): IProduct | undefined` — возвращает товар по идентификатору;
- `setSelected(product: IProduct): void` — сохраняет товар для подробного отображения;
- `getSelected(): IProduct | null` — возвращает выбранный товар.

Конструктор не принимает параметров.

### Класс Basket

Хранит товары, выбранные покупателем для покупки. Один товар не может быть добавлен дважды.

Поле `items: IProduct[]` содержит товары в корзине.

Конструктор не принимает параметров.

Методы:

- `getItems(): IProduct[]` — возвращает товары корзины;
- `addItem(product: IProduct): void` — добавляет товар;
- `removeItem(product: IProduct): void` — удаляет товар по идентификатору;
- `clear(): void` — очищает корзину;
- `getTotalPrice(): number` — возвращает общую стоимость товаров, товары без цены учитываются как `0`;
- `getCount(): number` — возвращает количество товаров;
- `hasItem(id: string): boolean` — проверяет наличие товара по идентификатору.

### Класс Buyer

Хранит и валидирует данные покупателя. Данные можно сохранять частично, не удаляя ранее сохранённые значения.

Поле `data: Partial<IBuyer>` содержит введённые данные покупателя.

Конструктор не принимает параметров.

Методы:

- `setData(data: Partial<IBuyer>): void` — сохраняет одно или несколько значений;
- `setPayment(payment: TPayment): void` — сохраняет способ оплаты;
- `setAddress(address: string): void` — сохраняет адрес;
- `setEmail(email: string): void` — сохраняет email;
- `setPhone(phone: string): void` — сохраняет телефон;
- `getData(): Partial<IBuyer>` — возвращает данные покупателя;
- `clear(): void` — очищает данные;
- `validate(): BuyerErrors` — возвращает объект ошибок по незаполненным полям.

### Класс LarekApi

Использует переданный API-клиент для получения каталога и отправки заказа. Класс не хранит данные и не работает с DOM.

Конструктор `constructor(api: IApi)` принимает объект базового API-клиента.

Поле `api: IApi` хранит переданный клиент.

Методы:

- `getProducts(): Promise<IProductsResult>` — выполняет GET-запрос на `/product/`;
- `createOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на `/order/` и передаёт данные заказа.

В `main.ts` создаются экземпляры всех моделей, вызываются их методы с выводом результатов в консоль, после чего выполняется запрос каталога и его сохранение в `Products`.
